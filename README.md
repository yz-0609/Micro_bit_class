# 易碎品运输记录系统（micro:bit V1 基础版）

当前使用精简版：冲击、持续倾斜、开箱事件检测，累计次数与最近 16 条事件，蜂鸣提示及电脑查看、CSV / JSON 导出。板端只用内存保存本次记录，断电、重启或开始下一次运输会清除旧记录；需要留存时先导出到电脑。

## 硬件连接

| 器件 | 接口 | 用途 |
|---|---|---|
| 碰撞模块 | 对应 P1 的传感器口 | 模拟箱盖开关 |
| 电位计 | 对应 P2 的传感器口 | 启运前选择低、中、高三档灵敏度 |
| 扩展板蜂鸣器 | P0 | 事件短音提示，打开板上蜂鸣器开关 |
| micro:bit USB | 电脑 | 供电、串口查看与导出 |
| 板载加速度计 | 无外接线 | 冲击和相对初始姿态检测 |
| 板载 LED、A/B | 无外接线 | 状态显示、开始 / 结束、静音 |

J3 及与 LED / 按键复用的 J4/J5/J6 留空。无需接马达、舵机或其他模块。2026-10-21 更换的 micro:bit V1 串口为 COM42，重新插拔后以实际枚举结果为准。

## 使用方法

1. 双击 `启动运输记录器.cmd`，选择串口，点击“连接设备”。
2. 模块调试时按住碰撞开关模拟合盖，将主控板放稳，转动电位计选择灵敏度。
3. 点击“开始运输”或按 A：立即采集当前重力方向作为姿态基准，并锁定灵敏度。开始时应保持静止。
4. 运输期间松开开关触发开箱；持续倾斜超过约 45 度、约 2 秒触发倾斜；合加速度达到所选阈值触发冲击。
5. 点击“结束运输”或再按 A。点击“读取记录”查看本次摘要与事件，然后点击“导出 CSV 与摘要”。导出的 CSV 旁会生成同名 JSON。
6. 按 B 或点击“静音 / 恢复”切换蜂鸣器提示，检测继续运行。

默认合盖电平为 1。实际安装到箱盖后若电平相反，可在电脑端两步调整：合盖稳定后点击“① 标定合盖”，开盖稳定后点击“② 标定开盖”。该调整只在本次通电期间有效。

## 显示与判定

- 待机显示 1 / 2 / 3，代表低 / 中 / 高灵敏度。监测显示 `R`，事件发生后显示最新事件 `S`（冲击）、`T`（倾斜）、`O`（开箱）；准确次数在电脑端查看。
- 本板按 ±2g 量程工作，三档阈值分别为约 1.75g、1.50g、1.25g；数值以开始时采集的重力幅值归一化。
- 冲击事件记录首次越过阈值的采样值；持续超阈值不重复计数，回落至阈值约 85% 以下并满足 500 毫秒间隔后允许再次计数。全程最大采样加速度另行累计。
- 倾斜超过约 45 度持续约 2 秒记录一次；回到约 35 度以内后可再次记录。合加速度明显偏离 1g 时暂停倾斜计时。
- 碰撞开关使用 60 毫秒消抖，只记录合盖到开盖的变化。
- 主循环约每 20 毫秒运行一次，实际周期包含运算和串口传输时间。这里检测的是采样加速度，不是冲击力；短促冲击可能漏过采样点。
- 记录时间为启运后毫秒；累计次数持续增加，详情只保留最新 16 条。开始下一次运输前请先导出。

## 文件与维护

- `docs/板上代码关键阅读与答辩速查.md`：面向课程答辩的代码阅读导航、算法解释、常见追问、演示步骤和三分钟讲解稿。
- `firmware/parcel_mu.py`：Mu 可直接刷入的独立单文件版，包含下列四个板端文件的全部逻辑，只依赖 micro:bit 内置模块。已通过原有 8 项检测逻辑测试及本机 Mu 1.2.0 打包检查；本次生成时开发板未连接，尚未进行单文件版上板运行验证。
- `firmware/parcel_main.py`：板端入口，部署后为板上的 `main.py`。
- `firmware/parcel_core.py`：基础判定、计数与 16 条缓存。
- `firmware/parcel_hardware.py`：真实传感器采样、LED、按键及蜂鸣器。
- `firmware/parcel_actions.py`：串口命令及记录读取。
- `host/parcel_monitor.py`：电脑界面；`host/parcel_protocol.py`：协议及 CSV / JSON 导出。
- `host/deploy_parcel.py`：备份、上传与逐文件读回校验。
- `tests/`：基础判定与电脑协议测试。运行 `python -m unittest discover -s tests -v`。
- `host/verify_parcel_board.py`：专用于首次调试的自动板端验证；会生成模拟事件并在结束时重启清除，只能在没有真实运输记录时运行。
- `verification/parcel_basic_verification/`：模拟测试导出、真实采样稳定性日志与结果。带 `SIMULATED_TEST_ONLY` 的文件是测试数据，不是实际运输数据。

## 使用 Mu 刷入单文件版

1. 将 micro:bit 通过 USB 连接电脑，关闭电脑端运输记录器的串口连接。
2. 打开 Mu，点击“模式”，选择 BBC micro:bit。
3. 点击“加载”，打开 `firmware/parcel_mu.py`，点击“刷入 / Flash”，等待完成。
4. 只需这个 `.py` 文件，无需通过“文件”面板再传输其他模块。Mu 会将它作为板上的 `main.py` 运行。
5. 待机时 LED 显示 1 / 2 / 3。按住碰撞开关、放稳主控板后按 A 开始，重新按 A 结束；B 切换提示音。电脑界面和导出方法不变，连接前关闭 Mu 的 REPL / 绘图器以释放串口。

单文件版与四文件版的检测规则及串口协议相同；修改四文件版后也需同步更新单文件版。

## 开发、部署与检查

电脑端使用 Python 3 和 Tkinter，附带 pySerial 离线副本。若使用系统安装的 pySerial，可执行：

```powershell
python -m pip install -r host/requirements.txt
python host/parcel_monitor.py
```

四文件版部署（会备份并替换板端应用）：

```powershell
python host/deploy_parcel.py --port COM42
```

无硬件即可运行的测试：

```powershell
python -m unittest discover -s tests -v
```

板端初次调试工具支持 `--port` 参数，默认 COM42；串口变化时请显式指定。`verify_parcel_board.py` 会生成模拟事件并在结束时重启清除，不应在存在待保存的真实运输记录时运行。旧验证日志保留其生成时的日期、串口及历史路径。
